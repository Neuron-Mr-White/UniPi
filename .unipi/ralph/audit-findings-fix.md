# Fix Proven Audit Findings — Check → Fix → Test

Use `.unipi/docs/research/unreachable-useless-code-audit.md` as the source inventory. Address each stated finding through an explicit **Check → Fix → Test** cycle. Work on one finding per iteration unless an approval gate consumes the iteration.

## Mandatory approval rule (user directive)

Before editing production code for any finding that is uncertain, is a breaking change, or may alter runtime/code behavior:

1. Re-check the current source and tests first.
2. Explain the exact proposed behavior/API change and risks.
3. Ask the user for explicit approval with `ask_user`.
4. Do not implement that finding until approval is received.

Approval is per finding/iteration, not blanket approval. If the safest outcome is documentation, deprecation, hiding a setting, or retaining a public API, present the alternatives. Preserve unrelated working-tree changes.

## Per-finding cycle

For every checklist item:

- **Check:** Reproduce/revalidate the defect against current source, package artifact, or runtime. Confirm expected behavior from docs/tests/types. If the report is stale or wrong, update it and do not force a fix.
- **Gate:** Ask before uncertain, breaking, compatibility-sensitive, or behavior-changing work.
- **Fix:** Make the smallest coherent correction. Do not mix unrelated cleanup.
- **Test:** Add focused regression coverage; run package tests/typecheck/build as appropriate.
- **Record:** Update this task Notes and `.unipi/docs/research/unreachable-useless-code-audit.md` with status, files, tests, and any deferred decision.
