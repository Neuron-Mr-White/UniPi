# DeepSeek `(prior reasoning summary unavailable)` — Debug Report

## Summary
The string is not generated by UniPi/Pi code. It arrives from upstream OpenAI-compatible reasoning streams (mostly Omniroute-routed reasoning models) as `reasoning_content`, and Pi faithfully persists/displays it as a thinking block.

## Expected Behavior
Reasoning-capable models either stream useful reasoning text, stream no reasoning text, or hide reasoning cleanly without noisy placeholder text.

## Actual Behavior
Some routed reasoning models repeatedly produce a thinking block containing exactly:

```text
(prior reasoning summary unavailable)
```

This appears in session JSON as:

```json
{"type":"thinking","thinking":"(prior reasoning summary unavailable)","thinkingSignature":"reasoning_content"}
```

## Reproduction / Evidence
Commands used:

```bash
rg -n "prior reasoning summary unavailable|reasoning summary unavailable|prior reasoning" \
  ~/.pi ~/.config ~/.local/share . 2>/dev/null
```

Findings:

- No Pi/UniPi/pi-ai source file contains the literal string.
- Session files contain many persisted assistant thinking blocks with that string.
- A scan of `~/.pi/agent/sessions/**/*.jsonl` found 1356 occurrences.

Top affected models from session history:

- `openrouter/z-ai/glm-5.2` via `omniroute`: 1080
- `deepseek/deepseek-v4-flash`: 75
- `openrouter/deepseek/deepseek-v4-flash-0731-xhigh`: 75
- `ds/deepseek-v4-flash`: 74
- `openrouter/deepseek/deepseek-v4-flash-0731`: 26

So this is not exclusively a DeepSeek issue; it is broader to reasoning summaries from routed OpenAI-compatible providers, with DeepSeek Flash variants also affected.

## Root Cause Analysis

### Failure Chain
1. Pi requests an Omniroute/OpenAI-compatible reasoning model with thinking enabled.
2. The upstream gateway/model streams a `reasoning_content`/reasoning delta whose text is the placeholder `(prior reasoning summary unavailable)`.
3. `@earendil-works/pi-ai` maps OpenAI-compatible reasoning fields to Pi thinking blocks in `openai-completions.js`.
4. Pi persists that block in the session and renders it as model thinking.
5. On later same-model turns, Pi's `transformMessages`/`convertMessages` may replay same-model thinking blocks with `thinkingSignature: "reasoning_content"` back into the provider history, as required by some DeepSeek tool-continuation formats. That can keep the placeholder visible in subsequent turns.

### Root Cause
Upstream providers/gateways return a placeholder string when a prior reasoning summary is unavailable/redacted. Pi has no filter for this exact placeholder, so it treats it like normal reasoning text.

## Affected Files / Code Paths
- `@earendil-works/pi-ai/dist/api/openai-completions.js`
  - Parses streaming reasoning deltas from fields `reasoning_content`, `reasoning`, `reasoning_text` and emits thinking blocks.
  - Replays same-model thinking blocks using the stored `thinkingSignature` field.
- `~/.pi/agent/models.json`
  - Omniroute dynamic models have only basic fields (`id`, `reasoning`, `input`, etc.) and generally lack per-model `compat` metadata. This means Omniroute-routed DeepSeek/OpenRouter models are handled by generic OpenAI-compatible defaults unless overridden.

## Suggested Fix
Two separate fixes are possible depending on goal:

1. **UI/noise fix:** Filter exact known placeholder reasoning text before creating/storing a thinking block.
   - If a reasoning delta equals `(prior reasoning summary unavailable)`, ignore it or mark the block redacted/empty.

2. **Provider-compat fix:** Ensure Omniroute dynamic models carry correct `compat` metadata based on model ID prefix.
   - `deepseek/...` and `ds/...`: DeepSeek-style thinking/reasoning compatibility.
   - `openrouter/...`: OpenRouter-style nested `reasoning` compatibility.

## Verification Plan
1. Run a tool-using turn with `omniroute/deepseek/deepseek-v4-flash` or an affected GLM model.
2. Confirm no visible thinking block contains `(prior reasoning summary unavailable)` after the filter.
3. Confirm actual reasoning text still appears for providers that stream useful reasoning.
4. Confirm tool continuation still works for native DeepSeek models that require `reasoning_content` history.

## Notes
Short-term user workaround: set thinking off for the affected models or use a non-reasoning/non-routed model. DeepSeek V4 Pro sessions in history often contain real short reasoning text; Flash/Omniroute/OpenRouter Flash variants show the placeholder more often.
