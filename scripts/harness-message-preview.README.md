# UNI-49 design preview — harness-origin user-content distinction

`harness-message-preview.ts` is a standalone, deterministic DESIGN PREVIEW of how
harness-generated messages that arrive as user content (Ralph/progress guard,
kanboard, memory, plan mode, watchdog, …) would be distinguished from human-typed
text. **It is not the live renderer and changes nothing live**: no pi session, no
LLM, no model-role or transport changes, no settings writes. Every panel carries
the header chrome **"DESIGN PREVIEW — no live renderer or model-role changes"**;
presentation labels are never injected into a payload.

## The proposed distinction (three densities)

- **Human text** — pi's real native `UserMessageComponent` on pi's own built-in
  dark theme, loaded and installed in-memory via `setThemeInstance` (that is the
  only theme override, and it is pi's default dark palette), plain `YOU`
  label in the comparison, content unchanged. Harness text is never rendered as
  an anonymous user block.
- **Harness panels** — ONE slate-violet `▏` rail `#a78bfa` on a dark-slate fill
  `#20222d` on every painted row (blanks included), content rendered at
  width-2 so wrapped words are never cut; detail rows and footers wrap instead
  of truncating (no cyan `#12363b`/`#22d3ee`, no orange summary rules):
  - `simple` — one `◇ UniPi · <source> · <short title>` row, one state/synopsis
    line (fixture metadata, not text heuristics), `e: full message` indicator;
    expanded shows the full markdown behind a neutral rail.
  - `regular` — label + the full markdown card, no collapse by default;
    `e` toggles metadata/details only, the body is never hidden.
  - `advanced` — label + first 4 rendered markdown rows, expand for the rest,
    footer `origin: harness | model role: user | delivery: …`.
- **Warnings** (runaway guard, kanboard nudges, watchdog) keep the violet
  provenance identity and add a warning glyph ⚠ with a readable warning tone.
- **Special panels** — `tool-result annotation` (fusion nudges, kanboard R1,
  watchdog kill: appended to tool results, *not* user messages), `hidden`
  (`display:false`, never rendered), and `existing dedicated renderer; not
  redesigned` stand-ins for background-task/sidekick/subagent completions
  (already distinct — never shown as raw XML human messages).
- Every event is its own panel; unrelated sources are never merged.

## Run

```sh
scripts/uni-harness-preview.sh                       # interactive TUI, simple style, mixed scenario
scripts/uni-harness-preview.sh --print               # static: gallery + mixed, all styles
npx tsx scripts/harness-message-preview.ts --help    # all flags
npx tsx --test scripts/harness-message-preview.test.ts   # focused tests
```

Flags: `--interactive` (launcher default), `--print` (all styles), `--plain`,
`--style simple|regular|advanced`, `--fixture <id>|all`, `--scenario
mixed|gallery|both`, `--width N`, `--expand`, `--help`. Unknown style/fixture
exits 2. Interactive seeding precedence: an explicit `--scenario` always wins;
otherwise a specific `--fixture` opens the gallery on that fixture; with
neither, the browser opens on the mixed scenario.

Panels show human-friendly source labels (Ralph, Kanboard, Progress guard,
Memory, Watchdog, …); the technical fixture id sits in the `d` details rows.
Goal kickoff/continuation/recovery/wrap-up and the fusion nudges are generated
by importing the pure source modules (`prompts/goal.ts`, `fusion/prompts.ts`) —
tests assert fixture equality to catch drift; other source-dependent texts are
embedded as exact static excerpts (named per fixture) or marked `synthetic
demo output` where the real text is dynamic.

On coffee: `~/uni-harness-preview.sh` (isolated `~/uni-harness-preview-iso/`,
same flags; node resolved from the mise installs dir).

## Fixtures

Each fixture is labeled with its fidelity: **exact source text** — generated by
importing the pure source modules (goal kickoff/continuation/recovery/wrap-up,
fusion nudges; asserted byte-equal by tests) or embedded as an exact **static
source excerpt** where the formatter isn't importable without side effects
(kanboard `doText` registers settings; Ralph reads the loop task file) — or
**illustrative** (`synthetic demo output` in the details: dynamic texts like
doctor/recall results, completion stand-ins, and the width-stress panel). No
thinking fixtures exist in this preview; the assistant rows are clearly labeled
stand-ins with demo text, not reasoning transcripts.

The mixed scenario is chronological: human request → assistant stand-in →
generated kanboard-do panel (the `Request:` user text stays verbatim payload
data, split only by a label row) → demo tool → kanboard R1 tool-result
annotation → runaway-guard steer (top-level message) → assistant stand-in →
Ralph iteration → kanboard-autowork wrapper → memory-consolidation wrapper →
watchdog custom warning batch → existing background-completion stand-in → human
reply (which quotes "No-progress guard:" and must stay YOU). The full source
classification lives in `scripts/harness-message-inventory.md`.

Keys in `--interactive`: `1/2/3` style · `n`/`←→` fixture (event anchors in
mixed) · `m` mixed/gallery · `e` expand · `d` details · `↑↓`/`pgup/pgdn` scroll
· `q`/`esc` quit (terminal restored).
